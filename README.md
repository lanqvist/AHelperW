# AHelperW

**Для продолжения разработки:** [память проекта](docs/PROJECT_MEMORY.md)
содержит актуальную архитектуру, особенности APL/API, историю проверок,
ограничения и состояние релиза. Правила входа в проект — [AGENTS.md](AGENTS.md).

Контрастный HUD и Windows-ридер для World of Warcraft 12.1 (Midnight).
Аддон отображает состояния способностей, ауры, ресурсы и контекст боя;
ридер распознаёт HUD, выбирает действие по адаптированной APL и при включённых
автонажатиях отправляет назначенную клавишу. Применение подтверждается отдельным
пиксельным журналом событий аддона, без OCR.

Игровые проверки выполнены на клиенте **12.1.0.69933**; пакеты APL закреплены за
**12.1.5.70448** ([переход на 12.1.5](docs/patch-12.1.5.md), в игре на нём не проверены). В аддоне есть наборы HUD для 40
специализаций; исполнитель APL поддерживает только перечисленные ниже профили.

| Профиль APL | Статус | Проверка в игре |
|---|---|---|
| Arms / Slayer (71) | `game-observed` | чтение, ротация и подтверждения применений |
| Fury / Slayer (72) | `experimental` | одна и несколько целей, два персонажа |
| ВВ / Шадо-Пан (269) | `experimental` | персонаж 81-го уровня, ресурсы, комбо и основной «Зенит» |
| Frost DK / Deathbringer, Rider (251) | `in-development` | Deathbringer: одна и несколько целей; Rider ещё не проверен полностью |
| Unholy DK / Rider, San'layn (252) | `in-development` | San'layn: одна и несколько целей; у Rider остаются ограничения |
| Retribution / Templar, Herald of the Sun (70) | `in-development` | Templar: первый автоматический бой 43/43 событий применения, общая кнопка Judgment/Hammer; Herald и спорные ауры требуют проверки, в установщик ещё не включён |

Это адаптации закреплённых APL SimulationCraft, а не полное исполнение всех
условий SimC. Статусы и результаты — в [памяти проекта](docs/PROJECT_MEMORY.md).

Личные экспорты HUD, назначения клавиш, журналы, окружение Python и локальное
состояние не входят в репозиторий. На новом компьютере нужен собственный экспорт
и назначения клавиш. Инструкции ридера: [reader/README.md](reader/README.md).

## Установочный пакет для Windows

Пакет **0.5.1** включает аддон **0.2.17**, ридер, Python и OCR-модели.
Опубликован как предварительный выпуск **v0.5.1**
в [Releases](https://github.com/lanqvist/AHelperW/releases).
Для закрытого репозитория нужен доступ к GitHub; скачанный установщик можно
передавать отдельно вместе с включёнными исходниками и лицензиями.
Выбери папку WoW или `_retail_`. Можно установить только ридер.
Перед обновлением аддона установщик сохраняет его старую папку в `Backups`
рядом с программой. Удаление программы сохраняет аддон, резервные копии и WTF.
В установленном ридере чтение и автонажатия изначально выключены.
Данные хранятся в `%LOCALAPPDATA%\AHelperW`. Подробности:
[инструкция установки](packaging/INSTALL.txt), [сборка из исходников](packaging/README.md).

### Первый запуск

1. Установи пакет, войди на персонажа и вне боя выполни `/reload`.
2. Для поддерживаемого профиля набор APL добавляется автоматически. При необходимости
   выполни `/ahw apl`. Через `/ahw config` выбери вид и положение HUD;
   легенду `/ahw preview` можно отключить для экономии места.
3. После изменения HUD подожди не менее двух секунд и сделай `/reload`:
   аддон обновляет экспорт, а игра записывает SavedVariables на диск.
4. Открой ридер. Он автоматически импортирует экспорт из найденной папки WoW.
   Для нестандартного пути при первом запуске используй `/ahw export`, затем
   «Вставить экспорт» или открытие сохранённого JSON/TXT. Не используй чужие координаты HUD.
5. Назначь клавиши способностей в ридере. Бинды и сохранённые HUD разделены по
   специализациям, но пока не по персонажам. Для Death and Decay нужен макрос
   `[@player]`, чтобы не оставался круг выбора точки.
6. Сначала нажми «Начать» **без автонажатий** и проверь чтение своего HUD.
   Затем при необходимости включи «Автонажатия по APL». **F8** останавливает исполнение.
   При потере фокуса WoW нажатия приостанавливаются; после возврата нужен свежий кадр.

Для манекена подходит тип боя «Постоянные цели — Patchwerk».
Число целей «Из HUD» — оценка наблюдаемых ближних врагов по неймплейтам;
`N+` обозначает нижнюю границу, `?` — недостаток данных.
Неизвестный прогноз конца боя или смерти цели не считается бесконечным временем.

## Установка

1. Скопируй папку `AHelperW` (ту, где лежит `AHelperW.toc`) в `World of Warcraft\_retail_\Interface\AddOns\`.
2. Шрифт JetBrains Mono уже включён в `AHelperW\Media\` вместе с лицензией OFL.
3. Перезапусти игру или сделай `/reload`.

## Команды

| Команда | Действие |
|---|---|
| `/ahw unlock` | разблокировать окно и перетащить мышью |
| `/ahw lock` | закрепить (клики проходят сквозь окно) |
| `/ahw dock left\|right\|off` | расположить у края; `off` возвращает сохранённую свободную позицию |
| `/ahw scale 1.5` | масштаб (0.5–3); для 4K рекомендуется ~1.5 |
| `/ahw alpha 0.9` | прозрачность чёрной подложки (0–1) |
| `/ahw palette cvd` | палитра для дальтоников (циан вместо зелёного); `default` — обратно |
| `/ahw cdtext on` | секунды на кулдаунах |
| `/ahw reset` | вернуть окно к левому краю |
| `/ahw spells` | показать набор текущего спека |
| `/ahw add 190319` / `/ahw del 190319` | добавить/убрать способность (spellID с wowhead) |
| `/ahw addproc 48108` / `/ahw delproc 48108` | добавить/убрать прок (ID ауры бафа) |
| `/ahw adddebuff 1943` / `/ahw deldebuff 1943` | добавить/убрать свой дебафф на цели |
| `/ahw default` | вернуть дефолтный набор спека |
| `/ahw config` | настройки вида, положения и экспорта (также кнопка у миникарты) |
| `/ahw editor` | ручной менеджер способностей/проков/дебаффов; также доступен в диагностике |
| `/ahw compact on\|off` | компактная или полная раскладка; после переключения подождать автоэкспорт и сделать `/reload` |
| `/ahw icons on\|off` | иконки внутри квадратов (цвет остаётся главным) |
| `/ahw auratimers on\|off` | таймеры действия баффов/проков |
| `/ahw armsapl` | дополнить набор под Arms/Slayer (патч 12.1.5), включить таймеры; вне боя |
| `/ahw apl` | добавить набор APL текущего поддерживаемого спека и героической ветки; вне боя |
| `/ahw furyapl`, `/ahw wwapl` | добавить набор Fury или ВВ; вне боя |
| `/ahw preview on\|off` | показать иконки и номера квадратов с компактной легендой справа; переключать вне боя |
| `/ahw context on\|off` | контекст боя: цели, касты, дистанция, время, предметы |
| `/ahw targets auto` | автоматическая оценка ближних целей по неймплейтам |
| `/ahw targets 1\|2\|3\|unknown` | ручной режим числа целей; также ЛКМ/ПКМ по ячейке |
| `/ahw ttd 60`, `/ahw fight 120` | ручные прогнозы времени смерти цели/конца боя; `unknown` очищает |
| `/ahw potion itemID` | выбрать зелье (можно перетащить из сумки на слот); 0 очищает |
| `/ahw trinket 1 buff 120 20 strength` | пример задания metadata тринкета: слот, вид эффекта, КД, длительность, сила |
| `/ahw stable on\|off` | постоянные цвета без вспышек; по умолчанию включено |
| `/ahw export` | статический JSON расположения HUD, ID, цветов, текущих талантов и экипировки |

## Цветовой язык

- **Ярко-зелёный** — КД завершён, проверка применимости пройдена; при наличии диапазона проверяется дистанция до цели. Линия видимости не проверяется.
- **Янтарный** — откатится в ближайшие 1.5 сек (вне боя; в бою см. ограничения)
- **Тёмно-красный** — на перезарядке
- **Синий** — откачена, но не хватает ресурса
- **Серый ×** — откачена, но сейчас неприменима (например, Казнь без условий).
- **Оранжевый Д** — цель вне диапазона способности.
- **Тёмно-янтарный ?** — данных не хватает. Не означает ни готовность, ни отсутствие баффа.
- Цифра в углу квадрата — заряды (Fire Blast, Shield Block и т.п.)
- Гибрид-квадрат: тёмный при 0, янтарный 1–4, ярко-зелёный на максимуме — «трать!»
- Руны ДК — 6 мини-квадратов: готовность, КД или неизвестно; рядом сила рун и время до следующей руны.
- **Маджента** — квадрат-прок: наблюдаемый бафф активен, с цифрой стаков; тёмный — бафф не отображается. Ауры рисует движок через AuraContainer; покрытие зависит от профиля и доступности ауры в клиенте.
- **Фиолетовый** — свой ДоТ/дебафф висит на текущей цели (Rupture, Agony, Ignite…), внутри — движковый отсчёт оставшихся секунд и стаки; тёмный — дот отвалился или цели нет
- Полоса здоровья цели и GCD: зелёный GCD готов, красный активен. Пороги для Arms — 20% и 35%, для «Смертельного касания» ВВ — 15%. Значения передаются в штатные виджеты WoW даже при Secret Values.

Подробное покрытие Arms/Slayer APL и оставшиеся ограничения:
[docs/arms-apl/README.md](docs/arms-apl/README.md).
Новый блок показывает наблюдаемые состояния и явно отмеченные ручные настройки.
Наличие HUD не подтверждает полноту APL или точность внешнего распознавания.

## Ограничения Midnight (Secret Values)

Blizzard в 12.0 закрыла аддонам «сырые» числа в бою. Что это значит здесь:

- Движок может отображать закрытые значения в штатных виджетах. Lua не читает их как обычные числа; ридер получает только изображение HUD. Неизвестное или устаревшее значение не подменяется нулём или готовностью.
- Янтарное «вот-вот» и цветовые пороги здоровья — только вне рестрикций (вне боя/энкаунтеров); в бою цифра ХП белая, но отображается всегда.
- Секунды на кулдаунах рисует штатный Cooldown-виджет (единственный разрешённый путь) — он показывает отсчёт всю длительность, а не только <10 сек.
- TODO: окраска ХП по порогам в бою через ColorCurve (`C_CurveUtil`) — требует проверки API в игре.

### Ограничения исполнителя APL

- Предметы, зелья и планирование Power Infusion не исполняются. Условия выбора
  между несколькими целями адаптированы под текущую выбранную цель.
- Каналы ожидаются целиком; ранние прерывания не реализованы, кроме отдельного
  правила Storm Bolt во время Bladestorm.
- ВВ при пустой истории и отсутствии маркера предыдущего удара может ждать
  первый ручной комбо-удар. Заменяющий удар «Зенита» пока отключён.
- У Unholy/Rider бафф Dark Transformation не виден в текущем канале HUD;
  связанные с ним условия, включая Putrefy, не доведены.
- Изменение положения/масштаба HUD требует нового экспорта. Ридер обнаруживает
  помеченные `stale` экспорты и старый журнал v1, но не любое изменение геометрии.
- Автоматический счётчик не видит всех врагов. Прогнозы TTD/конца боя задаются
  явно; их отсутствие может задерживать соответствующие правила.

Работу установщика на чистой Windows и игровые сценарии каждого профиля
нужно проверять отдельно. Успешная сборка пакета не подтверждает ротацию.

## Структура

- `Core.lua` — события, тикер обновления, инициализация
- `Layout.lua` — окно, подложка, перетаскивание, пиксель-чёткость, шрифты
- `Squares.lua` — квадраты способностей (состояние, заряды, вспышка)
- `Resources.lua` — здоровье, ресурс, гибрид-счётчик, руны
- `Display.lua` — нативное форматирование секретных чисел
- `CombatContext.lua` — контекст боя, касты, предметы, число целей и ручные прогнозы
- `Export.lua` — статический JSON схемы HUD и профиля
- `ClassData.lua` — маппинг спеков на способности (spell ID из ресерча 12.1, см. `docs/research-classes.md`)
- `Palette.lua` — палитры default/cvd
- `Options.lua` — команды `/ahw`
- `SpecProfiles.lua` — пакеты специализаций, пресеты APL и замены способностей
- `reader/spec_profiles.py` — реестр моделей APL, ресурсов и статусов
- `reader/*_apl.py`, `reader/apl_runtime.py` — выбор действий и вычисление условий
- `reader/saved_exports.py` — чтение экспортов из SavedVariables без изменения WTF
- `reader/input_sender.py`, `reader/cast_receipt.py` — отправка клавиш и подтверждения
- `packaging/` — автономный Windows-пакет, установщик и лицензии

ID, помеченные в ресерче как неподтверждённые, при отсутствии в клиенте автоматически скрываются (рантайм-валидация через `C_Spell.GetSpellInfo` + `IsPlayerSpell`).
