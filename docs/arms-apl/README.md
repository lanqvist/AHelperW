# Arms: аудит покрытия APL

**Исторический аудит исходной схемы HUD.** Затем появились Windows-ридер,
интерпретатор части APL, автооценка целей и подтверждение применений.
Текущая сводка — [PROJECT_MEMORY.md](../PROJECT_MEMORY.md). Таблица покрытия
ниже описывает начальный этап, а не полноту сегодняшнего исполнения.

Первый целевой спек: Arms (71), вместо Havoc. Экспорт пользователя сохранён
дословно в `build.txt`. Пользователь подтвердил клиент 12.1.0.69933 от Sep 18 2026,
Interface 120100 (`client.json`). Таблица `trait_data.inc` того же commit SimC
имеет в заголовке ровно этот build.

## Результат декодирования

`decoded-build.json`: сериализация v2, spec 71, героическое поддерево **60 / Slayer**.
Обработаны все 209 узлов класса, 597 бит и 3 нулевых бита дополнения.
76 записей включают выбор героической ветки и отдельные ступени Apex-таланта.
Проверены границы битового потока, индексы выбора, ранги и принадлежность спеку.
Хэш дерева в строке нулевой: независимую проверку хэша выполнить нельзя.
Факт применения этого билда в клиенте не проверен.

Выбраны Massacre (порог execute_phase ниже 35%), Dreadnaught, Fervor of Battle,
Bloodletting, Cleave, Opportunist, Imminent Demise, Tactical Edge, Deep Wounds,
Executioner's Precision, Collateral Damage, Avatar, Unrelenting Onslaught и
все ступени Master of Warfare. Demolish и Ravager в выбранных талантах отсутствуют.

`build-requirements.json` содержит только общие и Slayer-списки, значения
talent-гейтов. Runtime-условия не вычислялись. Требования экипировки и расовых
способностей остаются открытыми: их нет в строке талантов.

Повторить: `node docs/arms-apl/decode-build.mjs`, затем
`node docs/arms-apl/extract.mjs`. Таблица `warrior-traits.json` содержит строки
класса Warrior из generated/trait_data.inc; порядок записей сохранён.
Алгоритм следует generate_tree_nodes/parse_traits_hash в engine/player/player.cpp
того же commit. Для обновления таблицы передай путь к trait_data.inc аргументом
decode-build.mjs; чужая сборка отвергается.

## Источник

Получен исходник SimulationCraft из ветки `midnight`, commit
`b36fc0a2e299f925bc0f72375eea013d7ff5b1cf` (12.1.5.70448, с 17.10; до этого `4c7c736`,
12.1.0.69933 — APL Arms и дерево воина не изменились, `docs/patch-12.1.5.md`); ссылка и дата в `source.json`.
`apl_warrior.cpp` — сохранённый исходник, `requirements.json` — извлечённые
выражения только из функции Arms. Обновление отчёта: `node docs/arms-apl/extract.mjs`.
Это инвентаризация выражений, не интерпретатор APL. Версия таблицы талантов
совпадает со сборкой игрока; runtime-поведение требует проверки в игре.

## Покрытие текущим кодом

Состояние на 2026-09-28 после расширения HUD. `coverage.json` содержит
64 зависимости с источником данных и видом покрытия. Пересобрать:
`node docs/arms-apl/coverage.mjs`. Скрипт учитывает используемые переменные
транзитивно и останавливается при появлении зависимости без классификации.

| Вход | Реализация | Ограничение |
|---|---|---|
| Ярость / максимум | Основная цифра + ячейка максимума | Считыватель изображения ещё не реализован |
| КД / применимость / дистанция | Цвета ready, cd, nores, unusable, outofrange, unknown | Зелёный не гарантирует линию видимости/направление взгляда |
| Секретные usable/noPower | Два слоя Texture:SetShown с движковым показом | Lua не читает эти булевы значения обратно |
| cooldown.*.remains | Нативный Cooldown; десятые до 100 с при доступном форматтере | Без форматтера остаётся стандартный отсчёт |
| Overpower / Charge | Текущие заряды + восстановление следующего | Неизвестный максимум не скрывает currentCharges |
| Все перечисленные Slayer-баффы и стаки | AuraButton; форматтер показывает также 1 | При отсутствии API форматтера действует стандартное правило >1 |
| Avatar, Bladestorm, Battle Stance, PI | Отдельные ауры; PI допускает внешнего заклинателя | PI — чужой бафф; invoke_external_buff не кнопка воина |
| Heroic Strike | Мощный удар следует GetOverrideSpell; proc 1269391, cast 1269383 | Общий бинд с Slam указан в экспорте. 1269391 скрыта (атрибут 1 `0x10000000`, в игре не загоралась); квадрат прока с 30.09 красится по замене 1464 → 1269383 |
| Rend, Colossus Smash | Ауры текущей цели, таймеры | Другие цели не отслеживаются |
| target.health.pct | Полоса + 20/35 + числовой процент через движковый форматтер | Если форматтер недоступен, цифра «?», полоса продолжает работать |
| gcd.remains / gcd | Отдельный GCD 61304 + текущее haste | Базовый GCD вычисляет будущий читатель: max(0.75, 1.5/(1+haste/100)) |
| active_enemies | Явный ручной режим ? / 1 / 2 / 3+ | Не выдаётся за автоматический подсчёт |
| target_if=min:target.health.pct | Адаптация (17.10.2026): условие проверяется на текущей выбранной цели, цели не переключаются | Здоровье остальных врагов не видно; если выбрана цель выше порога, а другая уже в казни, выбирается slayer_st, а не slayer_execute |
| Каст и канал игрока/цели | Имя, нативная длительность, секретная interruptibility через SetShown | Недоступные API отмечаются «?» |
| time / движение / auto_attack | Время с входа в бой, скорость, индикатор автоатаки | После reload в бою начало неизвестно; точного movement.distance нет |
| Тринкеты | Слоты 13/14, активный эффект, КД, пассивность; ItemID/link/ilvl в экспорте | Класс эффекта, базовый КД и длительность баффа задаются как metadata |
| Зелье | Перетаскивание из сумки или itemID; наличие и КД | Пользователь выбирает предмет; отсутствие настройки явно видно |
| Таланты и раса | Текущая строка талантов, раса и экипировка в статическом JSON | Соответствие текущих талантов исходному билду ещё не вычисляется в аддоне |
| target.time_to_die / fight_remains | Ручные прогнозы с обратным отсчётом, по умолчанию ? | По истечении становятся неизвестными; TTD сбрасывается при смене цели |
| Успешное применение | ID из UNIT_SPELLCAST_SUCCEEDED + возраст события | Событие не равно попаданию/урону |

`raid_event.adds.*` встречается только в неиспользуемых `st_planning` и
`adds_remain`. Для этого сохранённого APL эти переменные не влияют на выбор
действия. Будущие версии APL нужно анализировать заново.

## Настройка и экспорт

- Расширение 2 один раз дополняет текущий набор Arms на патче из `ns.aplSource` (12.1.5), сохраняя
  пользовательские записи и их порядок; включает таймеры. Последующие ручные
  удаления остаются в силе. `/ahw armsapl` повторно добавляет недостающие записи.
- `/ahw context on|off`: дополнительный блок Arms под ресурсами.
- `/ahw targets 1|2|3|unknown`: ручной режим. На ячейке также работают ЛКМ/ПКМ.
- `/ahw ttd 60`, `/ahw fight 120`: прогноз в секундах. Вне боя отсчёт ждёт
  начала боя, в бою запускается сразу. `unknown` очищает значение.
- `/ahw potion itemID` либо предмет мышью в слот «ЗЕЛЬЕ». `0` очищает слот.
- `/ahw trinket 1 buff 120 20 strength`: для текущего первого тринкета указать
  бафф силы на 20 с и базовый КД 120 с. Это пример формата, не параметры
  конкретного предмета. Для прямого урона: `2 damage 90 0`.
  Metadata сохраняется по itemID, а не по позиции слота.
- `/ahw stable on|off`: постоянная заливка, без белых вспышек и GCD-сектора.
  По умолчанию включено для стабильного считывания цвета.
- `/ahw export`: вне боя открывает JSON для Ctrl+C. Там геометрия в физических
  пикселях от левого верхнего угла экрана, ID и типы квадратов, области
  таймеров/стаков, цвета, экипировка, текущие таланты, список неизвестных входов.
  Копия сохраняется в `AHelperWDB.lastHUDExport`. Это конфигурация, не поток
  боевых данных. После изменения масштаба/позиции/набора/талантов/экипировки
  экспорт нужно повторить.

## Проверка и пределы

`tests/run.cjs` проверяет синтаксис Lua 5.1, применение native secret sinks,
состояния неизвестности, смену каста/канала, зарядовый таймер, истечение и сброс
прогнозов, пустые/заблокированные предметы, миграцию набора и JSON экспорта.
Моки не воспроизводят WoW secure environment. Новые API/форматтеры и визуальная
верстка требуют проверки в клиенте; секретные поля нельзя считать доступными
Lua только потому, что их умеет нарисовать движок.

Полное выполнение произвольной APL не заявляется. В текущей версии уже есть
внешний считыватель и интерпретатор подмножества Arms/Slayer APL. Точный выбор
минимального HP среди всех врагов, будущая длительность боя и точное движение
из одного HUD не получаются. Ручные режимы и прогнозы — заданные условия,
а не автоматически измеренные факты. Автооценка целей по неймплейтам также
остаётся оценкой наблюдаемых ближних врагов.

при наличии, поскольку клиент пользователя 69933):
