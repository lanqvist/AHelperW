## 2. Цель и договорённости

Предпочтение в общении (28 сентября 2026, по просьбе пользователя): интересны
космос, тёмная материя и вопросы об устройстве Вселенной. Подходящие темы для
неформальной беседы; отличать наблюдаемые факты от гипотез.

Исходная идея: подвижное окно с максимально различимыми цветными квадратами,
пригодное для визуального чтения и внешнего pixel detection. Пользователь
предложил зелёный для готовой способности, красный для КД; ресурсы — цифрами.
Затем добавились менеджер наборов, превью, экспорт, диагностика, APL и
автонажатия. Также обсуждался стримовый обучающий оверлей: для него есть
машиночитаемый `state.json`, но отдельный готовый OBS-оверлей не реализован.

AutoHotkey не требуется текущему ридеру: исполнение сделано в Python через
Windows SendInput. `ahk/HavocBindings.ahk` — ранняя отдельная наработка,
не основной интерфейс и не исполнитель нынешнего Arms APL.

Приоритеты пользователя: контрастность, крупные читаемые цифры, небольшая
площадь HUD, настройка клавиш прямо в диагностике, минимум ручного выбора
числа целей, понятные причины пауз, решения по логам вместо догадок.
Код не читает память WoW и не реализует маскировку процессов/обход защиты.
Приватность репозитория не отменяет ограничений Blizzard на автоматизацию.

## 4. HUD, настройка и семантика

- Зелёный `ready`: КД завершён и доступные проверки применимости пройдены.
  Это не гарантия линии видимости или направления персонажа.
- Тёмно-красный `cd`: КД; янтарный `almost`: скоро готово при доступных данных.
- Синий `nores`: недостаточно ресурса; серый `unusable`: сейчас неприменимо.
- Оранжевый `outofrange`: вне дистанции; тёмно-янтарный `unknown`: данных нет.
- Маджента `proc`: активный бафф/прок; фиолетовый `debuff`: свой дебафф цели;
  тёмное состояние `procoff` — достоверное отсутствие в соответствующем канале.
- Основные ресурсы — цифры. Вторичные: гибрид цифры и заливки; DK — руны.
- Чёрная подложка, JetBrains Mono ExtraBold + OFL; есть альтернативная CVD-палитра.
- `/ahw stable on` убирает мешающие чтению вспышки; режим стабилизации цвета
  не означает, что все числа стали доступны Lua.
- Не сортировать квадраты динамически при появлении прока: фиксированный
  порядок/геометрия нужны ридеру.

Редактор разделён на **способности / баффы и проки / дебаффы**. В каждом
столбце есть добавленные элементы и кандидаты. Drag-and-drop меняет порядок
в допустимой категории. Не считать любой известный spellID допустимым баффом:
«Кровопускание» и дебафф «Удар колосса» принадлежат дебаффам цели.
Способность и её одноимённый бафф могут существовать одновременно в разных
категориях: пример — «Размашистые удары».

С 0.2.13 кнопка у миникарты и `/ahw config` открывают **настройки вида,
положения и экспорта**. Редактор — внутри диагностики или `/ahw editor`.
Пользователь подтвердил новое окно. Редактор сохранён; автоматическая
генерация всего набора из APL ещё не реализована.

### Компактный вид

- `/ahw compact on|off`, переключение вне боя. Сетка — 7 столбцов.
- Сохранены размеры квадратов и цифр; уменьшены отступы/служебные ячейки.
- Для Arms одна строка: HP игрока, ярость, HP цели, GCD.
- Большая легенда скрывается; иконки/номера превью можно оставить.
- Экспорт задаёт `contextNumbers` и `contextSamples` отдельно.
- Чёрно-белые цифры зарядов отделены от таймера и меток `Д`, `×`, `?`.
- В компактной полосе цели вертикальная отметка 35% попадала в OCR и
  превращалась в лишнюю единицу. Исправление: короткие отметки снизу,
  вне прямоугольника цифр. По следующему разбору боя дефект исчез.

## 5. Особенности WoW API и исправления

**Критичная дисциплина:** `issecretvalue` проверять до сравнения/арифметики/
строкового преобразования. Отображение движком не даёт права читать значение
обратно. Секретные поля аур, таймеров и чисел не использовать для Lua-ветвления.
Подробности раннего исследования API не универсальны для будущих сборок:
проверять реальный интерфейс целевого клиента.

Проки сначала не горели из-за вызова отсутствующего метода контейнера:

- Нужен `CreateFrame("AuraContainer", nil, parent, "CustomAuraContainerTemplate")`.
  У голого intrinsic нет `AddAuraSlot`/`AddAuraGroup`.
- `includeSpellIDs` — **map** `{ [spellID] = true }`, не массив `{spellID}`.
- `AddAuraSlot` возвращает кнопку с `CustomAuraButtonTemplate`.
- Настройка регионов — в `initializeFrame`; `SetApplicationCount` для стаков,
  `SetDurationCooldown` для таймера; позиционирование и настройка заранее.
- Движок управляет присутствием/отсутствием ауры. Нельзя получать скрытое
  состояние через OnShow, размеры, чтение текста или видимости кнопки.
- Для чужого Power Infusion нельзя требовать источник `PLAYER`.
- Для дебаффов нужен контейнер цели и обновление при смене цели.
- `/ahw procdebug`: присутствие ауры вне боя помогает проверить ID; `nil`
  при ограничениях не доказывает отсутствие баффа.

Стаки: formatter должен показывать также **1**, иначе стандартный вывод
часто отображает только значения больше единицы. Стак баффа, заряд способности
и секунды КД — разные величины. Исправлены «Неминуемая смерть» для «Вихря
клинков» и счётчик баффа «Размашистые удары»; пользователь подтвердил работу.

До фокуса на Arms пользователь проверял Warrior и Warlock. Для Demonology
аура **264173 «Сердце демона»** была обнаружена вне боя, а после исправления
AuraContainer пользователь подтвердил свечение проков в бою. В диагностике
также фигурировали 1276166, 433885, 433891 и дебафф цели 460553 «Рок».
Статус `engine` подтверждал настроенный способ отображения, а не наличие
каждой ауры и не полную проверку её ID/стаков. Отдельно пользователь подтвердил,
что «Провокация» стала корректно гаснуть; это не общая валидация всех контролей.

На последних скриншотах HP игрока отображался абсолютным числом (например,
770280), а HP цели — процентом. Не путать это с исходной проблемой «1%»
и не менять формат числа без согласования с областью OCR.

Другие исправления, которые нельзя потерять:

- Процентные API могут давать долю 0–1; масштабирование процентов выполняется
  native formatter (компонент `div=0.01`), не Lua-арифметикой над secret.
- Глобальный КД не должен создавать ложный отдельный КД на каждом квадрате;
  для GCD есть отдельный индикатор, используется spell 61304.
- Rebuild при смене талантов/спеллов/масштаба/спека; в бою перестройка
  откладывается и выполняется после выхода из боя.
- `UNIT_POWER_UPDATE` дополняет частое обновление; тикер 0.1 с нужен в том
  числе для конца КД, поскольку событие само по себе его не гарантирует.
- Состояние гибридного ресурса сбрасывается при перестройке; скрытый HUD
  не должен вызывать ненужную визуальную работу.
- Пустой ответ проверки range не равен false. Эталон Mortal Strike помогает
  для Arms, но неизвестность нельзя выдавать за подтверждённую дистанцию.

### Таланты и интерпретация

- Ридер проверяет spec 71 и совпадение build с таблицей.
- Декодируется экспорт талантов serialization v2. Активная hero tree берётся
  из **переключателя поддерева**, а не из автоматически выданных базовых узлов
  неактивной ветки: это уже было причиной ошибочного отказа запуска.
- Исходный билд включал Massacre (execute <35%), Dreadnaught, Cleave,
  Opportunist, Imminent Demise, Avatar, Unrelenting Onslaught и Apex.
- Работают выражения, переменные, приоритетные списки, одиночные/AoE/execute
  ветви в поддержанном подмножестве. Это **не полный движок SimulationCraft**.
- `Unknown` распространяется по выражениям; неизвестное условие применимого
  приоритетного действия может блокировать список, а не разрешать нижние кнопки.
- Неназначенные и неописанные действия сейчас пропускаются через available();
  нужен будущий явный отчёт покрытия, прежде чем переносить произвольные APL.
- `target_if` на нескольких целях блокируется: нет состояния всех врагов.
- `snapshot_stats`, `auto_attack`, `invoke_external_buff` не исполняются как
  обычные кнопки. Предметы/зелья присутствуют в HUD, но не являются готовой
  поддержкой use_items/potion. Часть trinket-условий остаётся неизвестной.
- TTD и fight_remains — ручные прогнозы; время боя измеряется отдельно.
  На манекене неизвестный TTD может задерживать Avatar и следующие действия.
  Режим манекена с явно длинным боем предлагался, но не считать реализованным.
- Точное movement.distance, будущие события рейда, LoS и оптимальный выбор
  цели не извлекаются из текущего HUD.

## 7. Экспорт и персональные данные

`/ahw export` доступен вне боя. `AHelperW.HUD`, version 1 — **статическая**
конфигурация, не поток боевых значений. Копия — `AHelperWDB.lastHUDExport`.
Координаты — physical pixels, начало top-left; содержатся rect, colorSample,
timerRegion/stackRegion, параметры вывода, ресурсы, контекст, таланты,
экипировка, aliases и `castSpellIDs` с доступными override.

Повторять экспорт после перемещения, масштаба, смены компактности/превью,
состава квадратов, талантов или экипировки. Старый профиль нельзя молча
применять к новой геометрии. Ридер проверяет размер клиентской области,
но не автоматически находит перемещённый HUD и не доказывает совпадение сцены.

Данные разработки: `reader/profile.json`, `reader/bindings/spec-71.json`,
`reader/logs`, `state.json`, `last_success.json`. Резервные профили сохранены
локально. Не включать эти данные, `.venv`, `.build-venv`, секреты и build/dist
в Git. Не заменять действующий экспорт примером ради сборки.

Установленная версия использует `%LOCALAPPDATA%\AHelperW`, а bundled assets
и APL находятся отдельно. Импортированный профиль сохраняется атомарно;
прежний — `profile.previous.json`. Без профиля показывается первый запуск.
В packaged-версии автонажатия **выключены при каждом старте**; development
сохраняет прежний включённый checkbox. Чтение в обоих случаях не стартует само.

## 8. Автоматическая оценка целей

Пользователь попросил убрать ручное переключение числа целей. TargetProbe
показал открытые ответы дистанции Mortal Strike для соседних манекенов в бою.
Это основание для оценки, не доказательство доступности данных в любом контенте.

- Скан `nameplate1..40` + токены событий; публичные UnitExists, UnitCanAttack,
  UnitIsDeadOrGhost и IsSpellInRange(12294).
- Период 0.2 с; стабилизация роста/нового числа 0.4 с, уменьшения 0.8 с.
- Неизвестные ответы или отсутствие подтверждённых ближних целей → `?`.
  Пропавшие неймплейты не означают ноль врагов.
- Причины кодируются отдельными цветами: estimate/manual/stabilizing,
  no_nameplates/no_melee_observation/range_unknown/unit_unknown/waiting.
- Изменение пикселей/статуса сбрасывает прежнее число до нового распознавания.
- `/ahw targets auto|1|2|3|unknown`; в ридере выбор «Из HUD» либо ручной.
- Нет точной общей картины всех врагов, их расстояний и здоровья.
- Избежать лишней паузы при смене числа внутри той же AoE-ветки предложено,
  но не реализовано: нельзя самовольно использовать устаревшее точное число.

## 9. Захват, OCR и публикация состояния

- `mss` захватывает сразу прямоугольник HUD вместо полного экрана с обрезкой.
  Есть backend Pillow. Настройка в `reader/pipeline.json`.
- Запрошен цветовой цикл 50 мс (20 Гц); это целевая частота, не гарантия.
  Поток OCR пробуждается новым кадром, не ждёт отдельного фиксированного сна.
- RapidOCR/ONNX Runtime, ограниченный batch (12), периоды по важности:
  rage/стаки ~0.15 с, цели ~0.2, haste/HP цели/скорость ~0.5,
  обычные таймеры ~0.6, часть контекста 1, HP игрока/maxrage 2 с.
- Дубли стаков связанного баффа используют alias вместо повторного OCR.
  Для бинарных аур цвет важнее числа; текстовые статусы не читаются как цифры.
- Кэш точного совпадения пикселей — до 10 с перед повторным OCR; это не
  общий классификатор цифр. Последний только обсуждался.
- Заряды белые на чёрном. При известном maxCharges выход за максимум отвергается.
  На цветовом потоке пиксели счётчика сверяются отдельно; смена цвета способности
  не обнуляет неизменную цифру. Изменение цифры → unknown до нового OCR.
- `capturedAt`, `recognizedAt`, `pixelValidatedAt`, `expiresAt` различаются.
  Скорость OCR-пакета не равна возрасту чисел при выборе действия.
- Потеря фокуса/размера/актуальности делает state недействительным.
- `state.json` — последний снимок с valid/expiry; `last_success.json` — явно
  **исторический**, не источник актуальных данных после остановки.
- StateWriter пишет temp + os.replace в отдельном потоке, отслеживает
  поколение запуска, повторяет ошибки sharing и не даёт старому кадру
  затереть остановку/новое поколение.

## 10. Исполнение и диагностика подтверждений

Назначения настраиваются в том же окне диагностики: колонка «Клавиша», двойной
щелчок; поддержаны модификаторы и некоторые кнопки мыши. Бинд — по способности,
не по её позиции. Heroic Strike использует Slam. F8 зарезервирована для остановки.

Перед отправкой: свежий валидный HUD, подтверждённая живая враждебная цель,
готовый GCD, состояние каста/канала, `inputAllowed` (чат/меню/смерть), фокус WoW.
Не нажимать при удерживаемых пользователем клавишах/модификаторах. Общий
guard GCD/off-GCD не универсален для всех классов. Есть специальный случай
Storm Bolt во время Bladestorm, а не полноценное управление каналами.

SendInput отправляет down/up одним пакетом. Минимальный интервал 0.3 с;
кадр перед отправкой не старше 0.3 с. При частичной вставке очищаются только
клавиши данного пакета и возникает ошибка. Не поднимать привилегии ради ввода.

После отправки исполнитель ждёт изменение HUD до 1.2 с, затем переоценивает
APL. Предварительный выбор до конца GCD, очередь заклинаний, спам и ограниченные
повторы обсуждались, но **не реализованы**.

### Три разных факта

1. `key_sent`: Windows приняла пакет, ещё не факт применения.
2. `action_response_observed`: изменились КД/GCD/заряды, это косвенный отклик.
3. `action_cast_observed`: наблюдено новое событие нужного spellID после отправки.
   Не доказывает, что его вызвала программа, если был параллельный ручной ввод;
   также не доказывает попадание/урон.

### История применений без OCR

Поле «последний ID» перезаписывалось тиками Bladestorm и не различало повторы.
В `CastReceipt.lua` добавлена кольцевая история **4 × 56 бит**:
7 байт `[165, seqHi, seqLo, spellHi, spellMid, spellLo, checksum]`, checksum —
сумма первых шести mod 256; sequence 1..65535 с переходом через максимум.
Только открытые целые ID из player UNIT_SPELLCAST_SUCCEEDED, никаких secrets.

Ридер считывает чёрный ≤55 / белый ≥200, проверяет checksum и минимальную
геометрию 112×8 физических пикселей. Новая схема — `castReceipt.version=1`.
Без экспорта области — not_configured; не угадывать координаты.
Первая выборка задаёт baseline, старые события не подтверждают новые нажатия.
Окно сопоставления 2.5 с, учитываются базовые ID и overrides. Пропуски/сбросы
журнала отмечаются. `action_cast_unobserved` не равно доказанному провалу.
Эта диагностика добавлялась отдельно и сама не меняла способ отправки клавиш.

### Замер GCD

`gcd_timing.py` только измеряет, не планирует ввод. События:
`gcd_ready_observed`, `gcd_ready_wait`, `gcd_ready_window_end` с cycle.
Начало — первый ready-кадр после непрерывного cd, не начальная готовность
и не переход через unknown. Разрыв >250 мс делает наблюдение неточным.
`afterReadyObservationSeconds` — после захвата готового кадра;
`hudTransitionBracketSeconds` — неопределённость между кадрами, не серверное
время окончания GCD. Учитывать тикер аддона и рендер игры.

## 13. Как продолжать работу

1. Прочитать эту память и git status; узнать, какая копия ридера реально
   запущена: development и installed имеют разные данные и могут сосуществовать.
2. Сначала получить свежий лог нужного запуска/поколения. Сопоставить
   profile_loaded, схему receipt, ready/wait, key_sent и cast_observed.
3. Отличать возраст данных, задержку OCR, ожидание целей/GCD/канала и приём ввода.
   Не править тайминги на основании одного ощущения или общей частоты нажатий.
4. Изменения Lua нужно отдельно доставить в игровую папку аддонов и сделать
   /reload. Git push не обновляет установленную игру. Не перезаписывать WTF.
5. Для новой геометрии/состава — новый экспорт; перезапустить ридер при смене
   Python-кода. Не выдавать старый процесс за обновлённый.
6. Проверки в игре проводятся отдельно от сборки/синтаксиса; не приписывать
   их результатам установки. Не запускать боевой ввод незаметно для пользователя.

Полезные команды: `/ahw config`, `/ahw editor`, `/ahw compact on|off`,
`/ahw preview on|off`, `/ahw icons on|off`, `/ahw armsapl`, `/ahw export`,
`/ahw procdebug`, `/ahw targetprobe start|stop|report`, `/ahw targets auto`,
`/ahw ttd <секунды>|unknown`, `/ahw fight <секунды>|unknown`, `/ahw stable on`.

## 15. Приоритет источников

Текущий код + текущий целевой клиент + конкретный свежий лог сильнее старых
ресерч-таблиц. Эта память описывает состояние на указанную дату, не автоматическое
обновление на будущие патчи. `research-*.md` и первоначальный аудит APL оставлены
как происхождение решений, с непроверенными ID и историческими ограничениями.
При обновлении указывать, что именно реализовано, проверено в игре или только
предложено. Личные строки талантов/координаты/бинды извлекать из локального
профиля при необходимости, а не дублировать их в публикуемую память.
