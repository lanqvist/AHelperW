## Выводы

- Стаки и восстановление заряда уже доступны для более точных условий.
- Упрощённое правило не согласует Zenith с FoF/WDP: два применения пришлись
  на FoF с остатком более 16 с. Это отличие от ряда upstream-веток, но не
  доказательство, что все остальные upstream-ветки запрещали эти применения.
- Перенос всех upstream-веток сейчас опять упрётся в неизвестное время боя
  и отключённую модель предметов. Не подставлять выдуманное время.
- Семантика `unusable` проверена по `Squares.lua:GetSpellState`: это состояние
  возникает только в ветке отсутствующего собственного отката (или одного GCD),
  после проверки доступности. Поэтому resolver обоснованно возвращает нулевой
  остаток кулдауна; `APLRuntime.available` отдельно запрещает применение.
  Первоначальное подозрение на смешение этих состояний не подтвердилось.
- В одной upstream-ветке написано `cooldown.whirling_dragon.remains`;
  соответствие `whirling_dragon_punch` нужно проверить по SimC перед переносом.

Следующий этап: проверить разрешение имён, затем сравнить
условия доступных веток офлайн с учётом фактических талантов.

## Реализованная следующая адаптация

После аудита пользователь разрешил улучшение: правило расхода двух зарядов
плюс upstream-согласование по стакам/талантам/откатам без двух ограничений
времени жизни цели. Время боя не выдумывается. Исходный текст upstream-правила
сохранён в runtime как `upstreamSource`; изменение его структуры вызывает
явную ошибку загрузки, а не тихую замену другого правила.

Офлайн на шести прежних применениях: два с полными зарядами проходят,
четыре с одним зарядом откладываются. В остальных кадрах найдены 87 истинных
оценок условия согласования; это число кадров, не число применений и не
проверка доступности способности. Пропавшие заряды остаются unknown.
Нажатия при проверке не отправлялись. Улучшение DPS не измерено; новый бой
нужен, потому что изменение решения меняет дальнейшие ресурсы и откаты.
